# 時間軸與地圖操作

## 本次最小完整流程

建立地區或自建雨量站 → 新增事件 → 手輸座標或地圖選點 → 填時間、類型、內容與來源 → 定位、閱讀、編輯及匯出。

- 新增事件在未選地點時也有入口，手機另有頂列快速入口；事件表單明示所屬地點。
- 每筆事件可保存自己的 WGS84 座標，輸入介面亦支援 TWD97／TM2 121。兩個座標欄位都留白則沿用地點座標。
- 舊事件沒有獨立座標時，標示「沿用地點」，可用定位按鈕查看地點代表位置；修改地點座標會影響這類繼承定位。
- 雨量站為使用者自行輸入的站點，不代表官方站網，也沒有自動讀取即時雨量。
- 地圖顯示地區與站點，以及目前所選地點、目前篩選條件下的事件。事件點可開啟紀錄，時間軸有定位按鈕。同座標事件仍可能重疊，可從時間軸逐筆選取。
- 事件類型、選填的資料來源，以及系統產生的建立／最後修改時間，用於基本追溯。舊資料未曾記錄修改時間時顯示未記錄，不推估歷史修改時間。
- 日期篩選採臺灣日界且包含起訖日；與事件類型一併影響時間軸及事件地圖點。匯出仍包含此地點全部紀錄，對話框會說明。

## 網頁閱讀

- 一般維持 75% 螢幕寬度，可按「展開閱讀區」改為全寬，手機則使用全寬。
- 網頁與照片分頁呈現；事件資料可收合，讓內嵌網站保有可用高度。照片不再把網站往下推。
- 已確認 NCDR 設定 `frame-ancestors 'self'`，直接提供原站連結；其他網頁可手動展開「網頁無法顯示？」取得備援連結。沒有改寫或移除原站安全標頭。
- Google Drive 仍遵守原檔分享權限，分享調整後可重新載入預覽。

## 研究用途下一階段

這些是 WebGIS 專家檢視後的建議，尚未實作，也不增加本次表單負擔：

1. 定位方式與精度：GPS、地圖選點、里程推估及可信程度。
2. 來源與版本：表單編號、附件出處、修改歷程及個別使用者權限。
3. 標準交換：GeoJSON、CSV，以及包含照片檔的完整備份。
4. 長期比較：相同地點跨期照片、指標量化與品質檢查。
5. 有資料後再加站號、雨量值（mm）、累積時段與資料提供單位；不要只憑站點或「降雨」類別宣稱已取得雨量資料。

## 驗收

`npm test` 驗證座標、類型、來源、臺灣日期篩選及網址邊界；`npm run test:e2e` 驗證站點建立、獨立事件座標、地圖選點、舊版編輯相容、篩選同步、NCDR 備援，以及照片／網頁分頁和桌機、手機閱讀高度。新增欄位採加欄 migration，保留原有事件與附件。
